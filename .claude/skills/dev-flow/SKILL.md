# 開発ワークフロー（adv_ver2）

開発依頼を受けたら、以下の 4 ステップを **順番に** 進める。
**ステップ②でユーザーの OK をもらうまで、コード（.cs / .unity など）を一切変更しないこと。**

---

## ① 設計書の作成

ユーザーのプロンプトを解析し、まず関連する既存コードを読んで現状を把握してから、設計書を作成する。

### 手順
1. 依頼内容から「何を実現したいか」「どこに影響するか」を整理する
2. 関連ファイルを読み、既存のクラス・関数・シーン構成を確認する
3. 下記テンプレートに沿って設計書を作成する
4. 設計書は `Docs/Design/YYYYMMDD_機能名.md` に保存する（`Assets/` の外に置き、Unity にインポートさせない）
5. チャットにも設計書の内容をそのまま提示する

### 設計書テンプレート

```markdown
# 設計書：<機能名>

## 1. 概要
- 目的：<この開発で何を実現するか>
- 対象シーン：<00_Title / 01_Home / ... >
- 前提・制約：<既存仕様、依存関係など>

## 2. 処理の流れ
<Mermaid のフローチャートで処理・画面遷移を図示する>

## 3. クラス構成
<Mermaid のクラス図で、追加・変更するクラスと既存クラスの関係を図示する>

## 4. 追加・変更一覧

### クラス
| 区分 | クラス名 | ファイル | 機能 |
|---|---|---|---|
| 追加 / 変更 | | | |

### 関数
| 区分 | クラス名 | 関数名（シグネチャ） | 機能 |
|---|---|---|---|

### 変数
| 区分 | クラス名 | 変数名 | 型 | 機能 |
|---|---|---|---|---|

### Unity 側の作業（シーン・プレハブ・Inspector 設定）
| シーン / オブジェクト | 作業内容 |
|---|---|

## 5. 懸念点・確認事項
- <仕様が曖昧な点、ユーザーに決めてほしい点>
```

### 作成時のルール
- 図は Mermaid（`flowchart` / `classDiagram` / `sequenceDiagram`）で書く
- 追加・変更するクラス、関数、変数は **漏れなく** 一覧に載せ、名称と機能を説明する
- 既存コードの命名・フォルダ構成（`Assets/AppMain/NN_シーン名/Scripts/`、共通処理は `Assets/Scripts/`）に合わせる
- Inspector での参照設定やボタンの OnClick 登録など、コード外で必要な作業も明記する
- 仕様が曖昧な点は推測で埋めず「5. 懸念点・確認事項」に書く

---

## ② 設計書のチェック

設計書を提示したら、**必ずユーザーに確認を取って止まる**。

確認メッセージの例：
> この設計書の内容で実装を進めてよろしいですか？
> - OK なら「OK」とお伝えください。実装に進みます。
> - 修正が必要な場合は、修正内容を教えてください。設計書を直して再提示します。

### 分岐
- **OK の場合** → ③ 実装へ進む
- **修正依頼の場合** → 指摘内容を反映して設計書（ファイルも）を更新し、変更点を明示したうえで再提示 → 再び ② の確認に戻る
- OK が出るまでこのループを繰り返す

---

## ③ 実装

確定した設計書どおりに実装する。

- 設計書に書かれていない変更は行わない。実装中に設計変更が必要だと分かった場合は、手を止めてユーザーに相談し、設計書を更新してから続ける
- 既存コードのスタイル（コメントの量、命名、`Debug.Log` の使い方など）に合わせる
- `.meta` ファイルは Unity が生成するため手で作らない。新規スクリプトを追加した場合は「Unity エディタで一度フォーカスして .meta を生成すること」をユーザーに伝える
- `.unity` / `.prefab` の YAML は原則直接編集しない。シーン上の作業は ④ で手順としてユーザーに伝える
- コミットはユーザーから指示があったときだけ行う

---

## ④ 実装内容の説明

実装完了後、以下を **簡潔に** まとめて報告する。

```markdown
## 実装完了：<機能名>

### 変更ファイル
- [ファイル名](パス) — 何をしたか（1 行）

### 実装内容
- <主な処理の要点を 3〜5 行程度で>

### Unity エディタでの作業（必要な場合）
1. <オブジェクトへのアタッチ、Inspector 設定、OnClick 登録など>

### 動作確認方法
- <どのシーンで何をすれば確認できるか>

### 設計書との差分・注意点（あれば）
- <設計から変えた点、未対応の点、既知の問題>
```
